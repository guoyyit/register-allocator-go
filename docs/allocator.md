# 寄存器分配与溢出决策

分配器位于 `internal/alloc`，把已校验的 IR 降低为目标指令，并在物理
寄存器不足时插入确定性的 `spill`/`reload`。

## 数据流分析（`liveness.go`）

- 以基本块为节点做标准的 live-in/live-out 不动点迭代。
- 对每条（按块展平的）指令同时计算：
  - `LiveIn`/`LiveOut`：该点前后的活跃虚拟寄存器集合；
  - `NextUse`：沿 CFG 可达的最近一次后续使用的指令下标；
  - `LiveAtExit`：函数返回点仍活跃、属于可观察终态的寄存器。
- 跨 CFG 边传播“下次使用”时，只接受在后继块入口已经活跃的值，避免
  把后继块内“先定义后使用”的值误当成入口处的未定义使用。

## 在线分配（`emitter.go` / `regs.go` / `lower.go`）

逐条指令发射，维护：

- 每个虚拟寄存器当前是否在某物理寄存器中、对应哪个寄存器；
- 每个物理寄存器是否空闲、当前由哪个 vreg 占用；
- 每个 vreg 是否 `dirty`（寄存器中的权威值比栈槽新）；
- 指令处理期间被“保留”（reserved）的源寄存器，不能被其它操作数抢走。

### 溢出决策

需要一个物理寄存器而没有空闲时，选择驱逐对象：

1. 优先选择“下一次使用最远”（或本指令后不再使用）的占用值；
2. 距离相同时选择物理编号最大的寄存器，保证结果确定；
3. 被驱逐值若为 `dirty`，先发射 `spill` 写入它的专属家槽，再复用寄存器；
   干净值只更新映射，不产生额外存储。

每个虚拟寄存器在第一次需要溢出时获得一个确定编号的专属栈槽
（按首次分配顺序 `s0, s1, ...`），整个函数内复用同一个家槽。

### 正确性约束的处理

- 二元三地址指令：目标寄存器必须与两个源都不同；不足时驱逐“其它”
  活跃值，绝不覆盖任一源。`store` 的地址与值寄存器也强制不同。
- 同一 vreg 在一条指令中被读两次允许别名（值相同）。
- 立即数源放入只在该指令期间存活的 scratch 寄存器，指令发射后回收。
- 控制流边界：在每个非 `ret` 终结指令之前，把之后仍活跃的脏值全部
  `spill`；在后继块入口，寄存器状态被视为全部来自家槽，首次使用时
  按需 `reload`。这样所有前驱汇入后继时看到同一份规范状态，不需要
  phi 或寄存器移动解析。
- 调用点：先把所有驻留脏值落盘（callee 会破坏全部寄存器），再依次把
  实参从其家槽 `reload`（或立即数 `li`）到 `r0..rk-1`，结果绑定到 `r0`。

## 确定性

分配过程不使用随机数、map 迭代顺序或环境信息：

- 物理寄存器、栈槽、驱逐比较的遍历都按固定整数升序/显式平局规则；
- 函数、块、指令按源码顺序处理；
- 相同输入与相同物理寄存器数量产生逐字节相同的目标汇编
  （`target.MProgram.String()`），回归测试强制比对。
