# 目标机器模型

目标机是一个简单的 load/store、三地址、无限栈槽的抽象机器，由
`internal/target` 解释执行。

## 资源

- `N` 个物理寄存器 `r0..rN-1`，`N` 在编译时固定（`alloc.Config.NumPhysical`，
  默认 4；最小 3，因为二元指令要求目标与两个源互不相同）。
- 每函数私有的溢出栈槽 `[s0..]`，数量在编译期确定，访问不越界。
- 所有函数共享一块按字编址、初始全零的内存。

## 调用约定（固定）

- 全部物理寄存器都是 caller-saved：`call` 会破坏 `r0..rN-1` 的全部内容。
- 参数经 `r0..rk-1` 传递，形参在被调函数入口就位于这些寄存器。
- 整数返回值经 `r0` 传递。

因此任何“跨调用存活”的虚拟寄存器都必须在 `call` 之前显式写入自己的
栈槽，需要时在 `call` 之后重载；分配器对调用点就是这样做的。

## 指令

| 指令 | 语义 |
| --- | --- |
| `li rd, imm` | 立即数装载 |
| `mov rd, rs` | 寄存器拷贝 |
| `add/sub/mul rd, rs1, rs2` | 三地址运算，`rd` 与两个源不同 |
| `cmplt rd, rs1, rs2` | 小于，写 0/1 |
| `load rd, rs` | `rd = mem[rs]` |
| `store rs1, rs2` | `mem[rs1] = rs2` |
| `label name:` | 代码标签（跳转目标） |
| `b L` / `bnez rs, Lt, Lf` | 无条件/非零条件跳转 |
| `call f -> rd` | 调用，结果在 `r0` 并移入 `rd` |
| `ret rs` | 返回 `rs`（约定为 `r0`） |
| `spill rd, [sk]` | `slot[sk] = rd`（溢出计数 +1） |
| `reload rd, [sk]` | `rd = slot[sk]`（恢复计数 +1） |

## 可观察状态与等价性

IR 直接解释与目标代码解释的“最终状态一致”定义为：

- `main` 的返回值一致；
- 共享内存每个字一致；
- 在 `main` 返回点仍活跃的虚拟寄存器，其值在目标机的寄存器或栈槽中
  与 IR 帧一致（死寄存器的值不可观察，不做比较）。

目标解释器还统计整个执行过程中的 `spill`/`reload` 指令条数，供基准
回归与溢出上限测试使用。
