# register-allocator-go

一个用 Go 实现的寄存器分配代码生成后端：输入是带基本块与控制流的、
基于虚拟寄存器的中间表示（IR），在仓库内完成解析、校验、寄存器分配、
溢出与目标代码生成，并通过一个目标机解释执行器做端到端语义验证。

## 目录

- `internal/ir` — IR 定义、解析器、语义校验器、IR 直接解释执行器。
- `internal/target` — 目标机模型、解释执行器、确定性汇编打印。
- `internal/alloc` — 活跃性/下次使用分析、寄存器分配与溢出、代码降低。
- `internal/codegen` — 解析→校验→编译的门面。
- `benchmarks` — 基准 IR 程序、可自动校验的溢出数量上限与回归测试。
- `cmd/ra` — 命令行工具。
- `docs` — [IR 规范](docs/ir.md)、[目标机模型](docs/target.md)、
  [分配器设计与溢出决策](docs/allocator.md)。

## 快速开始

```sh
go build ./...
go test ./...

# 编译并同时执行 IR 与目标代码，比较最终状态
go run ./cmd/ra -regs 4 -run benchmarks/benchdata/high_pressure.ir
```

命令行参数：

- `-regs N`：物理寄存器数量（默认 4，最小 3）。
- `-mem N`：共享内存字数（默认 1024）。
- `-run`：同时执行 IR 与目标代码并比较内存、返回值与活跃寄存器。

## 保证

- **语义等价**：目标代码执行后的内存、返回值与返回点活跃寄存器与 IR
  直接执行完全一致（差分测试 + 随机模糊测试覆盖）。
- **正确溢出**：活跃值超限时插入 `spill`/`reload`，脏值被覆盖前必先
  落盘；同一物理寄存器不会同时承载两个活跃值。
- **调用约定**：全 caller-saved，参数走 `r0..`、返回走 `r0`；跨调用
  存活值在调用前后完整保留。
- **拒绝非法输入**：未定义值、格式错误、损坏控制流等返回带行号的错误。
- **确定性**：相同输入产生逐字节相同的目标代码，不依赖随机数或环境。
- **质量回归**：`benchmarks` 中强制执行每程序的溢出指令数量上限，
  防止分配质量退化。
